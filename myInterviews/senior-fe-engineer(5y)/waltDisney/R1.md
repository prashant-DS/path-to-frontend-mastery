## 1. Reading Time

The first functional requirement was to calculate and display the reading time for each article.

Two approaches were discussed.

### Approach A — Calculate during data transformation

```js
const articlesWithReadingTime = articles.map((article) => ({
  ...article,
  readingTime: calculateReadingTime(article.content),
}));
```

Then JSX only needs to render:

```jsx
<span>{article.readingTime} min read</span>
```

### Approach B — Calculate during rendering

```jsx
<span>
  {calculateReadingTime(article.content)} min read
</span>
```

### Discussion

We also discussed that derived data does not necessarily need to be stored in React state. It can be calculated or memoized depending on how expensive the computation is and whether it needs to be reused.

## 2. Related Articles

Each article contained an array of related article IDs:

```js
{
  id: 1,
  title: "Introduction to React",
  relatedArticleIds: [2, 4]
}
```

The requirement was to display the related article titles/details in the UI.

Since the initial article response only contained IDs, additional API calls were required.

### Approach Discussed — One API Call Per Related Article

For each article, iterate over its `relatedArticleIds` and call the article API for each ID.

Conceptually:

```js
for (const id of article.relatedArticleIds) {
  const relatedArticle = await getArticle(id);
}
```

This was the approach I used considering the time available.

### Alternative Approach Discussed — Batch Fetch

If the API supported fetching multiple articles by ID, we could first collect all required IDs:

```js
const ids = [
  ...new Set(
    articles.flatMap((article) => article.relatedArticleIds)
  ),
];
```

Then make a single API request for those IDs.

This would reduce the number of network requests, especially when multiple articles reference the same related article.

## 3. Async Patterns

We discussed the differences between common approaches for handling multiple asynchronous API calls.

### `for...of`

```js
for (const id of ids) {
  await getArticle(id);
}
```

- Executes sequentially.
- Useful when requests depend on one another.
- Not ideal when all requests are independent.

### `forEach`

```js
ids.forEach(async (id) => {
  await getArticle(id);
});
```

- `forEach` does not wait for async callbacks.
- Should not be used when we need to await completion of all requests.

### `Promise.all`

```js
const relatedArticles = await Promise.all(
  ids.map((id) => getArticle(id))
);
```

- Executes independent requests concurrently.
- Useful when we need to fetch multiple independent resources.
- Rejects if one of the promises rejects.

## 4. `useEffect` Implementation

The related article fetching was performed inside `useEffect`.

The pattern discussed was:

```jsx
useEffect(() => {
  const fetchRelatedArticles = async () => {
    // fetch related articles
    // update state
  };

  fetchRelatedArticles();
}, [articles]);
```

Rather than making the effect callback itself async:

```jsx
// Avoid
useEffect(async () => {
  // ...
}, []);
```

The async function is defined inside the effect and then invoked.
